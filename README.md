# Video Saver Bot + изолированный Downloader + Local Bot API + MeTube

Бот скачивает публичные видео из Instagram, YouTube, VK Видео и TikTok и отправляет
файлы до **2 000 000 000 байт (2000 МБ)** через собственный Telegram Bot API Server.
MeTube остаётся отдельным веб-интерфейсом для скачивания на сервер.
Четыре сервиса работают в Docker Compose. Local Bot API бесплатен; оплачивается инфраструктура.

## Настройка

Нужны Linux, Docker Engine, Docker Compose и минимум около 7 ГБ свободного места
для одной задачи с максимальным размером 2 ГБ. Кеш/состояние API и загрузки MeTube требуют дополнительного места.

```bash
git clone https://github.com/Maks113/video-saver-bot.git
cd video-saver-bot
cp .env.example .env
chmod 600 .env
```

Заполните `.env`:

- `TG_BOT_TOKEN`: текущий токен от BotFather.
- `TG_ALLOWED_USER_IDS`: разрешённые числовые Telegram ID через запятую.
- `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`: получите на https://my.telegram.org/apps.
- PUID, PGID: UID/GID бота (по умолчанию 1000:1000).
- DOWNLOADER_UID: отдельный непривилегированный UID загрузчика, по умолчанию 65532.
  Он обязан отличаться от PUID. Групповые права открывают только нужные направления обмена.
- `METUBE_URL`: адрес вашего MeTube, например https://ha-dashboard.space/metube/.
- `MAX_UPLOAD_BYTES`: до 2000000000; `DOWNLOAD_TIMEOUT`: 1800 секунд по умолчанию;
  `UPLOAD_TIMEOUT`: 7200 секунд по умолчанию, отдельно от короткого тайм-аута polling.

## Переключение с облачного Bot API

```bash
bash scripts/switch-local-api.sh
```

Если Docker требует административных прав, выполните команду через sudo.
Скрипт проверяет настройки и место на диске, собирает образ и проверяет запуск Local Bot API.
Только после этого останавливает старого бота, вызывает облачный `logOut`, проверяет
локальный `getMe` и запускает polling на локальном сервере.
API доступен только в сети telegram, статистика — только на loopback API-контейнера.
Белый IP, домен и входящие порты не нужны.

До облачного запроса сохраняется намерение logout_requested. Запись атомарна:
файл и содержащий каталог синхронизируются через fsync до отправки RPC.
Если ответ потерян, запрос отменён или процесс упал, повторный запуск НЕ вызывает
облачный logOut автоматически и пробует локальную авторизацию.

Состояния в приватном data/bot-state/.local-api.json:
- logout_requested: результат облачного запроса неизвестен;
- logout_rejected: получен явный отказ; обычный повтор остановится до обращения к облаку;
- cloud_logged_out: получено подтверждение облачного выхода;
- ready: облачный выход и локальная авторизация подтверждены;
- ready_unconfirmed: локальная авторизация работает, но исход прежнего logOut неизвестен.

getMe на локальном API не доказывает, что прежний облачный запрос был исполнен.
При ready_unconfirmed полнота получения обновлений не гарантируется Telegram:
https://core.telegram.org/bots/api#logout.
Это неопределённость сетевого RPC; маркер не скрывает её под видом подтверждённого выхода.
После проверки причины оператор может явно повторить облачный запрос:

    bash scripts/switch-local-api.sh --retry-cloud-logout

Флаг не вызывает повтор для уже подтверждённых cloud_logged_out/ready.
Автоматического сброса маркера, повтора облачного RPC и отката в облако нет.
После успешного logOut облачная авторизация недоступна 10 минут.
При неудачной локальной проверке polling остаётся выключенным.
Нельзя запускать старый и новый polling одновременно.
Процедура: https://github.com/tdlib/telegram-bot-api#switching.

Скрипт предназначен для облако → Local Bot API на одном сервере.
Для переноса уже работающего Local Bot API на другой сервер используйте официальную
процедуру и перенос состояния: https://github.com/tdlib/telegram-bot-api#moving.
Не копируйте только маркер миграции без соответствующего состояния API.

На Ubuntu без Docker: `sudo bash scripts/install-server.sh` устанавливает Docker/Compose
из репозиториев Ubuntu, выполняет переход, если секреты заполнены. MeTube автоматически не запускается.

## MeTube и авторизация

`docker compose up -d metube` запускает веб-интерфейс.
По умолчанию он слушает только localhost:8081. Для внешнего доступа используйте
HTTPS reverse proxy с авторизацией, включая API, WebSocket и скачивание файлов.
Публичный адрес задаётся в `METUBE_URL`; префикс /metube/ и авторизация настраиваются
на reverse proxy и в MeTube отдельно. Текущий Compose не публикует MeTube в интернете по умолчанию.
Не открывайте прямой порт в обход авторизации.

## Использование бота

- В личном чате пришлите ссылку или `/download ссылка`.
- В группе: `/download@M113_video_saver_bot ссылка`.
- Этой же адресованной командой можно ответить на сообщение со ссылкой в тексте или подписи.
- Доступ разрешён только `TG_ALLOWED_USER_IDS`; в группе результат виден всем.
- Анонимные администраторы/сообщения от имени канала не принимаются.
- Обычная ссылка в группе не запускает скачивание. В темах ответ приходит в исходную тему.
- `/help`, `/start` — справка; `/metube` — ссылка на MeTube; `/id` — свой ID в личном чате.
- Качество выбирается автоматически с предпочтением 720p по короткой стороне.
  Вертикальное 720×1280 поддерживается; если доступен только более высокий формат, он не отбрасывается.
- Подбора качества/аудио под старые 50 МБ больше нет. Лимит проверяется по итоговому файлу
  после объединения дорожек. Если он больше 2000 МБ, бот предлагает MeTube.
- Прямые эфиры и целые плейлисты не скачиваются; для публикаций с несколькими видео берётся первый элемент.
- Одна задача на пользователя во всех чатах и одна загрузка на сервере одновременно.
- Очередь хранится в памяти; после перезапуска ссылки нужно отправить повторно.

## Изоляция и хранение

Сети Docker разделены: telegram — только бот и Local Bot API;
download — только загрузчик с исходящим доступом к площадкам;
media — MeTube. Загрузчик и MeTube не подключены к сети API.
Статистика API слушает ТОЛЬКО 127.0.0.1:8082 внутри API-контейнера:
она может содержать токены, поэтому нельзя публиковать её или привязывать к 0.0.0.0.
Healthcheck работает из самого API-контейнера и не выводит тело статистики.

Бот и загрузчик используют отдельные PID namespaces и разные UID.
Загрузчик не получает TG_BOT_TOKEN, TELEGRAM_API_ID/TELEGRAM_API_HASH, каталог состояния
бота или его каталог отправки. Дочерний yt-dlp получает только явно разрешённые
переменные среды (PATH, locale, временный каталог/кеши, пути CA), без Telegram-секретов.

Направления файлового обмена:
- data/download-requests: пишет бот, загрузчик читает read-only;
- data/download-results: пишет загрузчик, бот читает read-only;
- data/worker-downloads: пишет загрузчик, бот читает read-only;
- data/bot-uploads: приватная копия бота, загрузчик её не видит; API читает read-only;
- data/bot-state: приватный маркер миграции и блокировка экземпляра бота;
- data/bot-api и data/bot-api-tmp: приватное состояние и временные файлы API;
- data/metube/downloads и data/metube/state: загрузки, история и настройки MeTube.

Ответ загрузчика считается недоверенным: размер JSON ограничен, разрешены только
фиксированные имена видеофайлов. Для чтения используются открытые дескрипторы каталогов
и O_NOFOLLOW; FIFO, каталоги, симлинки и файлы вне каталога задания не принимаются.
Бот копирует ограниченными порциями в свой закрытый каталог и отправляет API только
file:///uploads/... . Загрузчик не может подменить этот путь после проверки.
Это дополнительная копия на диске, а не загрузка гигабайтного файла целиком в RAM.

Удаление запроса отменяет задание/освобождает файлы загрузчика.
Временные копии бота удаляются после отправки/ошибки/отмены; после перезапуска
под эксклюзивной блокировкой удаляются остатки прерванных заданий.
Дорожки и объединение контролируются по размеру и свободному месту, сохраняется резерв 1 ГБ.
Копирование в закрытый каталог также проверяет свободное место.
Журналы каждого сервиса ограничены тремя файлами по 10 МБ.
Состояние API и сохранённые через MeTube видео требуют отдельного контроля места.

Одноразовый prepare-storage запускается с UID 0, без сети, с ограниченными capabilities
и только перечисленными bind mounts, чтобы назначить владельцев каталогов.
У работающих бота, API и загрузчика нет root/capabilities/Docker socket.
При обновлении старого layout маркер из data/bot-downloads копируется в приватный
data/bot-state; старые пользовательские данные не удаляются.

## Cookies и секреты

Некоторые площадки требуют cookies или ограничивают IP сервера.
Положите Netscape cookie-файлы в `cookies/youtube.txt`, `cookies/instagram.txt`,
`cookies/vk.txt` или `cookies/tiktok.txt`. Загрузчик получает каталог cookies read-only и использует временную копию исходника;
Для Instagram сначала выполняется попытка без авторизации. Только при явном отказе
в доступе (например, требовании входа или ограничении аудитории) загрузчик повторяет
попытку с `cookies/instagram.txt`, если файл существует. Ошибки сети, лимит размера
и ограничение частоты запросов сами по себе не вызывают такую повторную попытку.
Обе попытки используют общий тайм-аут. Для других площадок cookies используются сразу.
Обновление файла не требует перезапуска; автоматического продления сессии нет.
Файл должен читаться загрузчиком (UID 65532, группа PGID; например, группа 1000
и права 640 при стандартной настройке). Не публикуйте cookies и не отправляйте их в чат.
Cookies MeTube загружаются отдельно через его интерфейс.
`.env`, cookies и весь `data/` исключены из Git и контекста сборки.
Состояние API также является приватными данными. Резервные копии храните закрыто.

## Обновление и проверка

После успешной миграции:

```bash
git pull --ff-only
bash scripts/switch-local-api.sh
docker compose --profile bot ps
docker compose --profile bot logs --tail=100 -f
```

Первый запуск и обновление выполняйте через scripts/switch-local-api.sh:
он собирает образ, готовит UID/права и проверяет сервисы. Для состояния ready
повторный запуск не обращается к облачному logOut.
Образы MeTube и Local Bot API закреплены тегом/дайджестом. Для API используется
образ проекта aiogram/telegram-bot-api с официальным бинарником tdlib (Bot API 10.3).

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
python -m coverage run -m unittest discover -s tests -v
python -m coverage report
python -m coverage html
docker compose --env-file .env.example --profile bot config --quiet
docker build -t video-saver-bot:test .
```

CI проверяет тесты, покрытие строк и ветвей (порог 95%), Compose и сборку.
HTML-отчёт сохраняется как артефакт. Тесты работают без сети и не отправляют сообщения.
Они проверяют реальный селектор yt-dlp на фиксированных метаданных, локальные пути,
переход с logOut, повтор миграции, дисковый резерв, очистку, процессы, группы и темы.
Проверки ресурсов включают 240 заданий и повторные реальные subprocess-запуски.
Они не заменяют наблюдение за длительной работой и проверку конкретных ссылок площадок.

Тесты скачивания подставляют фиксированную доступную ёмкость диска:
проверки процессов, отмены и форматов не требуют 7 ГБ на машине с тестами.
Отдельные тесты нехватки места задают нулевой остаток и истощение резерва во время
загрузки/копирования. Производственная проверка диска при этом не отключена.
CI также проверяет сетевую изоляцию и настройки секретов через scripts/check-isolation.py.

Проверка всей той же тестовой сборки при сообщаемых 512 КБ свободного места:

    python scripts/test-small-disk.py

В CI эта проверка обязательна и не заполняет настоящий диск.

## Малая VPS

Для 1 vCPU / 1 ГБ RAM / 5 ГБ свободного SSD используйте .env.small.example,
лимит 250 МБ и compose.small.yaml. MeTube выключен по умолчанию (профиль web).
Подробный перенос работающего Local Bot API: [DEPLOY-SMALL.md](DEPLOY-SMALL.md).
