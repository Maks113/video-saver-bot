# Video Saver Bot + MeTube + Local Bot API

Бот скачивает публичные видео из Instagram, YouTube, VK Видео и TikTok и отправляет
файлы до **2 000 000 000 байт (2000 МБ)** через собственный Telegram Bot API Server.
MeTube остаётся отдельным веб-интерфейсом для скачивания на сервер.
Три сервиса работают в Docker Compose. Local Bot API бесплатен; оплачивается инфраструктура.

## Настройка

Нужны Linux, Docker Engine, Docker Compose и минимум около 7 ГБ свободного места
для одной задачи с максимальным размером 2 ГБ. Кеш/состояние API и загрузки MeTube требуют дополнительного места.

```bash
git clone https://github.com/Maks113/video-saver-bot.git
cd video-saver-bot
cp .env.example .env
chmod 600 .env
```

Заполните `.env`:

- `TG_BOT_TOKEN`: текущий токен от BotFather.
- `TG_ALLOWED_USER_IDS`: разрешённые числовые Telegram ID через запятую.
- `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`: получите на https://my.telegram.org/apps.
- `PUID`, `PGID`: UID/GID владельца данных на сервере (по умолчанию 1000:1000).
- `METUBE_URL`: адрес вашего MeTube, например https://ha-dashboard.space/metube/.
- `MAX_UPLOAD_BYTES`: до 2000000000; `DOWNLOAD_TIMEOUT`: 1800 секунд по умолчанию;
  `UPLOAD_TIMEOUT`: 7200 секунд по умолчанию, отдельно от короткого тайм-аута polling.

## Переключение с облачного Bot API

```bash
bash scripts/switch-local-api.sh
```

Если Docker требует административных прав, выполните команду через sudo.
Скрипт проверяет настройки и место на диске, собирает образ и проверяет запуск Local Bot API.
Только после этого останавливает старого бота, вызывает облачный `logOut`, проверяет
локальный `getMe` и запускает polling на локальном сервере.
API и статистика доступны только в Docker-сети: белый IP, домен и входящие порты не нужны.

Успешный `logOut` фиксируется до локальной авторизации. Если последняя не удалась,
повторный запуск скрипта продолжает переход без обращения к облаку.
До подтверждения миграции бот отказывается запускать polling.
После облачного `logOut` возврат к облачному API запрещён Telegram примерно на 10 минут;
автоматического отката в скрипте нет. Нельзя одновременно запускать старый и новый polling.
Процедура: https://github.com/tdlib/telegram-bot-api#switching.

Скрипт предназначен для облако → Local Bot API на одном сервере.
Для переноса уже работающего Local Bot API на другой сервер используйте официальную
процедуру и перенос состояния: https://github.com/tdlib/telegram-bot-api#moving.
Не копируйте только маркер миграции без соответствующего состояния API.

На Ubuntu без Docker: `sudo bash scripts/install-server.sh` устанавливает Docker/Compose
из репозиториев Ubuntu, запускает MeTube и выполняет переход, если секреты заполнены.

## MeTube и авторизация

`docker compose up -d metube` запускает веб-интерфейс.
По умолчанию он слушает только localhost:8081. Для внешнего доступа используйте
HTTPS reverse proxy с авторизацией, включая API, WebSocket и скачивание файлов.
Публичный адрес задаётся в `METUBE_URL`; префикс /metube/ и авторизация настраиваются
на reverse proxy и в MeTube отдельно. Текущий Compose не публикует MeTube в интернете по умолчанию.
Не открывайте прямой порт в обход авторизации.

## Использование бота

- В личном чате пришлите ссылку или `/download ссылка`.
- В группе: `/download@M113_video_saver_bot ссылка`.
- Этой же адресованной командой можно ответить на сообщение со ссылкой в тексте или подписи.
- Доступ разрешён только `TG_ALLOWED_USER_IDS`; в группе результат виден всем.
- Анонимные администраторы/сообщения от имени канала не принимаются.
- Обычная ссылка в группе не запускает скачивание. В темах ответ приходит в исходную тему.
- `/help`, `/start` — справка; `/metube` — ссылка на MeTube; `/id` — свой ID в личном чате.
- Качество выбирается автоматически с предпочтением 720p по короткой стороне.
  Вертикальное 720×1280 поддерживается; если доступен только более высокий формат, он не отбрасывается.
- Подбора качества/аудио под старые 50 МБ больше нет. Лимит проверяется по итоговому файлу
  после объединения дорожек. Если он больше 2000 МБ, бот предлагает MeTube.
- Прямые эфиры и целые плейлисты не скачиваются; для публикаций с несколькими видео берётся первый элемент.
- Одна задача на пользователя во всех чатах и одна загрузка на сервере одновременно.
- Очередь хранится в памяти; после перезапуска ссылки нужно отправить повторно.

## Хранение и ресурсы

- `data/bot-downloads`: временные видео, маркер миграции и блокировка одного экземпляра.
- `data/bot-api`: постоянное состояние Local Bot API; `data/bot-api-tmp`: его временные файлы.
- `data/metube/downloads`: сохранённые пользователем видео, не удаляются автоматически.
- `data/metube/state`: история, настройки и cookies MeTube.

Оба контейнера используют одинаковый UID/GID и абсолютный путь `/downloads`.
API читает этот каталог только для чтения. Бот отправляет `file:///downloads/...`,
а не загружает гигабайтный файл в память или через multipart.
Временные каталоги удаляются после отправки/ошибки/отмены.
После аварийного перезапуска убираются оставшиеся каталоги `video-saver-*`;
эксклюзивная блокировка защищает активные задания другого экземпляра.
Перед загрузкой проверяется запас диска под дорожки и объединение; во время загрузки
поддерживается резерв 1 ГБ. Журналы каждого сервиса ограничены тремя файлами по 10 МБ.
Состояние API и скачанные через MeTube видео всё равно требуют контроля свободного места.

Процессы скачивания завершаются всей группой, даже если родитель уже вышел;
ожидание очистки ограничено. Удаление статуса не прерывает загрузку и отправку.

## Cookies и секреты

Некоторые площадки требуют cookies или ограничивают IP сервера.
Положите Netscape cookie-файлы в `cookies/youtube.txt`, `cookies/instagram.txt`,
`cookies/vk.txt` или `cookies/tiktok.txt`. Бот использует временную копию исходника;
cookies MeTube загружаются отдельно через его интерфейс.
`.env`, cookies и весь `data/` исключены из Git и контекста сборки.
Состояние API также является приватными данными. Резервные копии храните закрыто.

## Обновление и проверка

После успешной миграции:

```bash
git pull --ff-only
docker compose --profile bot up -d --build bot
docker compose --profile bot ps
docker compose --profile bot logs --tail=100 -f
```

Первый запуск выполняйте через `scripts/switch-local-api.sh`, а не напрямую.
Образы MeTube и Local Bot API закреплены тегом/дайджестом. Для API используется
образ проекта aiogram/telegram-bot-api с официальным бинарником tdlib (Bot API 10.3).

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
python -m coverage run -m unittest discover -s tests -v
python -m coverage report
python -m coverage html
docker compose --env-file .env.example --profile bot config --quiet
docker build -t video-saver-bot:test .
```

CI проверяет тесты, покрытие строк и ветвей (порог 95%), Compose и сборку.
HTML-отчёт сохраняется как артефакт. Тесты работают без сети и не отправляют сообщения.
Они проверяют реальный селектор yt-dlp на фиксированных метаданных, локальные пути,
переход с logOut, повтор миграции, дисковый резерв, очистку, процессы, группы и темы.
Проверки ресурсов включают 240 заданий и повторные реальные subprocess-запуски.
Они не заменяют наблюдение за длительной работой и проверку конкретных ссылок площадок.
